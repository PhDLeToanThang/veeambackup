#  Thực hành 4: Veeam ONE & Threat Center
## Data Platform Scorecard: 
Theo dõi 4 chỉ số cốt lõi: Platform Security Compliance, Recovery Health, Data Protection State, và Immutability Status.
## Phát hiện Ransomware: 
Cấu hình cảnh báo dựa trên sự thay đổi CPU bất thường và kích thước bản sao lưu tăng đột biến (Suspicious incremental growth > 85%).
## Chủ quyền dữ liệu: 
Sử dụng Threat Center để định vị địa lý các kho lưu trữ, đảm bảo dữ liệu không bị di chuyển ra ngoài vùng pháp lý cho phép.
## Kết luận: Giám sát thông minh là "tai mắt" giúp quản trị viên duy trì sức khỏe hệ thống và phản ứng tức thì với các mối đe dọa ẩn mình.

## Chi tiết:

Tài liệu này là một hướng dẫn thực hành chi tiết về Veeam ONE và Threat Center phiên bản V12.X, tập trung vào việc nâng cao khả năng phục hồi dữ liệu và bảo mật hạ tầng. Nội dung được chia thành các phần chính bao gồm giới thiệu tổng quan, phát hiện ransomware và cảnh báo, sử dụng bảng điều khiển (dashboard), thiết lập báo cáo và lập kế hoạch dung lượng, cũng như tích hợp các công cụ bên thứ ba như SIEM và ServiceNow. Mục đích cốt lõi của tài liệu là cung cấp cho các chuyên gia công nghệ kiến thức thực tế để tối ưu hóa bảo mật, theo dõi các mối đe dọa an ninh mạng, và quản lý tài nguyên hệ thống sao lưu một cách hiệu quả nhất.

Configure ServiceNow Settings
Since version 12.1 bi-directional integration with ServiceNow is available, allowing Veeam events to be automatically directed at the ServiceNow platform. This is configured within the Veeam ONE Client.
*Below is how to configure it via VeeamONE, for the scope of this Lab we don't have a ServiceNow test tenant to connect to but the details below describe how you would if you do have an instance to connect to.
1. Click to Maximise from Taskbar if you left it open in the SIEM Chapter, if not From the Desktop on the Management Server. > Double Click pr-ws22-vone1 RDP Icon.Then > Double Click on Veeam One Client. 
2. Ensure the Check Box Log in as current user is selected, > Click Connect. 
3. Click on the Menu Bar from the Top Left.> Click Settings > Server Settings. 
4. On the Left Hand Menu, > Click ServiceNow. > Enable ServiceNow Integration.
5. Type your Instance URL. > ServiceNow credentials. > ServiceNow incident configuration.
Information sent to ServiceNow can be defined here into Caller, Assignment Group and Close Code. Default Veeam values are sent if left null/blank. 
Caller — defines the caller name assigned for the purposes to create, update, and resolve incidents. Veeam ONE is the default value, alternatively you can define a custom name if it already exists on your ServiceNow instance.
Assignment group — defines the name for the assignment group for the purposes to create, update, and resolve incidents. Veeam ONE Support is the default value, alternatively you can define a custom name if it already exists on your ServiceNow instance.
Close code — defines the close code for resolved incidents. Use only the close code defined on your ServiceNow instance.
Additionally (and optionally) you can also select to automatically include information from a centralised Veeam knowledge base, to the ServiceNow platform. This could be useful, for example, sending alerts to a service desk where events and alerts are triaged to the correct department, providing useful initial information on the event. 
6. You can then test the connection to your ServiceNow instance 
7. Click OK when done, Or Click Cancel if you don't have a ServiceNow environment to connect to at the moment.
