Why protect Entra ID?
Image source: https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/cloud-governed-management-for-on-premises
Microsoft Entra ID (formally Azure AD) is a vital IT component for organisations of all sizes and in all industry verticals. Like Active Directory before it, Entra ID is becoming a standard in IT environments where authentication and central user-management are required. It’s almost impossible to imagine how IT system administrators would be able to do their jobs effectively if this technology didn’t exist.
Veeam Backup & Replication has supported application-aware backups for Active Directory for many years, but with the shift to Entra ID hosted by Microsoft in Azure, a new approach is required. The is the goal of the Entra ID backup feature in VBR 12.3: to provide a straightforward way for IT system administrators to protect the important data that controls User Identity management, and Application access within their organisation.
Microsoft provides some native tools for administrators to resolve Entra ID issues, such as the 30-day recycle bin. Although the Entra ID recycle bin can protect against some unfortunate mistakes, its power is limited as not all object types leverage the recycle bin. The recycle bin also does not protect from Object metadata changes - only soft-deletes.
Veeam Backup & Replication 12.3 adds the following features:
Secure, reliable backup and recovery for critical Entra ID objects
Back up and recover:
Users
Groups
Roles
Administrative Units
Application Registrations
Restore hard-deleted Objects even if they have been removed from the Entra ID recycle bin
Selectively restore individual Objects or specific Object properties
Bulk restore multiple Objects
Retain multiple backup versions
Easily compare data between backup restore points, and the live production environment
Overview of how Entra ID backup is implemented in VBR
Veeam Backup & Replication v12.3 introduces new features that enables Entra ID backup:
A new onboarding wizard to connect VBR to an Azure Tenancy.
A PostgreSQL database that's used as a new Backup Repository type specifically for Entra ID Objects.
An extension of the Unstructure Data backup process for Entra ID Audit Log backups.
There are no plugins or additional software required for Entra ID backup: everything is included in VBR 12.3. If PostgreSQL is not already deployed on the VBR server, it will be added as part of creating an Entra ID backup job.
Veeam Backup & Replication 12.3 has the ability to protect two Entra ID datasets: Object data, and audit log data.
In this lab environment, the following preparations/configurations have already been implemented:
VBR has been connected to an Azure Tenancy.
Two backup jobs have been created, one for the Tenancy Entra ID Objects, and another for the Audit logs.
Both jobs have been run once to create the initial backups.
Entra ID object backups are stored in a PostgreSQL database to facilitate incremental backups, point-in-time comparisons, and rapid restores. Only one Tenant backup job can be configured for each Microsoft Tenant.The Solution Architecture section of the Veeam User Guide for Microsoft Entra ID backups provides this solution architecture diagram:Note: click on any image shown in this guide to enlarge it
Backing up Entra ID Object DataThe following Entra ID tenant’s objects can be protected and restored:
Users
Groups
Administrative Units
Entra ID Roles
Application Registrations
A bespoke Veeam Explorer for these Entra ID Objects is included with VBR 12.3, which will be used later in this lab exercise.
Backing up Audit LogsAudit Log jobs protect the Tenant audit data (for example user sign-ins, provisioning logs, etc). Logs in Entra ID are read-only, so while backups can be created, log data cannot be restored to the production Tenant.
By default, Entra ID logs are stored in the production tenant for 30 days. This duration can be increased, and Microsoft also allows for logs to be archived to an Azure storage account for further analysis by Azure Monitor Logs or a third-party SIEM tool. These native log storage options will incurr additional cost from Microsoft, as outlined here: https://learn.microsoft.com/en-us/entra/identity/monitoring-health/concept-log-monitoring-integration-options-considerations
The option to backup and store logs in VBR provides a alternative option that enables organisations to store Entra ID logs in-line with other data protection best practises.
VBR leverages the Unstructured Data backup engine to capture Entra ID Audit logs. After authenticating with Azure, VBR copies Logs into a standard Veeam Backup Repository using the Unstructured Data backup format.
Backups can be made for the following Entra ID logs:
Audit logs
Sign-in logs (only for P2 subscriptions)
Audit Log data is dependant on already having a backup stored for the Entra ID Tenant Object data.
Due to the number of API calls required, capturing incremental backups for Audit Data requires more time to process than Entra ID Objects. In this lab environment, the Object Backup job takes 3-5 minutes to complete, but the Audit log backup job takes 50-60 minutes to complete.
If you would like to see the processes for adding an Azure Tenancy and creating backup jobs, these have been documented in the Supplementary Material section at the end of this guide.
